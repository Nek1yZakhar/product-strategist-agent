# TICKET-13: Реальная сквозная сессия агента и запись конкурсного видео (≤10 мин)

> **Статус**: PLANNED (волна 2, спринт-аудит 2026-11-22)
> **Приоритет**: P0 — обязательный материал конкурса («Видеозапись работы агента до 10 минут — обязательно»).

## 1. Контекст, проблема и инварианты (Context, Problem & Invariants)

### 1.1. Контекст и бизнес-проблема
Аудит выявил: видео не существует; `demo/session_transcript.jsonl` — это 10 строк ручной заготовки, а не реальный лог сессии (нарушение Zero-Mock Policy в текущей подаче). Конкурс требует сквозную демонстрацию: запрос → работа агента → варианты → стратегия → **продолжение после перерыва**. Существующие `demo/VIDEO-PLAN.md` (посекундная раскадровка) и `demo/RUNBOOK.md` (сценарий оператора) готовы к использованию — их нужно исполнить вживую.

### 1.2. Архитектурные инварианты
- **Real Run Invariant**: видео снимается с живого прогона агента в AntiGravity (Gemini 3.8 Flash) с реальным веб-поиском (grounding). Никаких заранее записанных «ответов агента».
- **Resume-After-Break Invariant**: обязательная сцена — закрытие чата, открытие НОВОГО окна, восстановление из `state/STATE-current-task.md` и пересмотр вывода при новой вводной (например: «МТС снизил цену участника до 99 ₽ — как это меняет вывод?»).
- **Fresh-Eyes Invariant**: перед записью выполняется чистый прогон с нуля (репетиция), запись — со второго прогона, чтобы исключить зависания и правки на ходу.
- **Cost-Truth Invariant**: во время живого прогона фиксируются реальные токены/время (заполнение `state/cost-log.csv` строками `entry_type: measured`).
- **Evidence Dependency**: прогон выполняется ПОСЛЕ TICKET-12 — агент в кадре ссылается на уже усиленные находки с глубокими ссылками.

### 1.3. Инструментальная база (проверенные ссылки)
- **Запись экрана**: OBS Studio — `https://obsproject.com` (1920×1080, 30 fps, кодек x264).
- **Терминальные реплеи** (опционально для монтажа вставок):
  - `https://github.com/BenLirio/claude-session-replay` — session.jsonl → самодостаточный HTML-реплей (чистый Python 3, без зависимостей), пауза/скорость 1×–8×, сжатие пауз.
  - `https://github.com/es617/claude-replay` — реплеи логов Claude Code / Cursor / Codex CLI / Gemini CLI / OpenCode, `--timing paced`.
- **Хостинг видео**: VK Видео или YouTube (unlisted) — оба формата разрешены регламентом.

## 3. Контракты и порядок операций

### 3.1. Pre-flight чеклист (до записи)
1. TICKET-12 принят (находки с глубокими ссылками).
2. `git pull` в рабочей копии; чистое состояние `git status`.
3. Репетиционный прогон от начала до конца, замер длительности; сокращение сцен до ≤9:50.
4. OBS: разрешение 1920×1080, масштаб интерфейса 125–150% (читаемость текста в кадре), тема IDE светлая или контрастная.
5. Микрофон: тест 10 секунд, проверка уровня.
6. **Red-Team ре-ран в Zcode выполнен** (контракт 3.3 ниже) — текущая версия `adversarial-review.md` создана основным агентом и не проходит приёмочный тест TICKET-09 (в ней нет контрмер 99 ₽ / ARPA 1 650 ₽ из контракта спеки); в кадре обязана быть реальная сессия GLM 5.3.

### 3.2. Пост-продакшн
1. Монтаж: срез пустых ожиданий (пауз агента) — допускается ускорение ×2 с титром «ускорено».
2. Титры блоков: «1. Repo-Agent», «2. Постановка задачи», … «6. Возобновление после перерыва».
3. Экспорт MP4 (H.264, ≤ 2 ГБ), проверка хронометража ≤ 10:00.
4. Загрузка на VK Видео / YouTube unlisted; проверка доступности ссылки в режиме инкогнито.
5. Вставка ссылки в `docs/SUBMISSION.md` (строка «Видеозапись работы») и в `docs/STATE.md` (журнал).

### 3.3. Контракт Red-Team ре-рана в Zcode (GLM 5.3)

**Проблема**: единственная glm-5.3 строка в `state/cost-log.csv` (02:07:00Z) встроена в синтетическую последовательность таймстампов волны 1, а `adversarial-review.md` не содержит контрмер из приёмочного контракта TICKET-09 (99 ₽/мес за IoT-устройство, ARPA ≥ 1 650 ₽). Вывод: ре-ран обязателен — и как честность данных, и как видимое доказательство кросс-модельной маршрутизации для критерия «Масштаб нейротехнологий» (до 10 баллов).

**Порядок**:
1. Открыть папку репозитория в Zcode (GLM 5.3).
2. Взять шаблон `knowledge/methodology/red-team/adversarial-review-prompt.md`; заполнить плейсхолдеры:
   - `{{PROJECT_NAME}}` → `demo-megafon`;
   - `{{BASELINE_METRICS_TABLE}}` → таблица из `knowledge/projects/demo-megafon/data/baseline-metrics.md` (после TICKET-12);
   - `{{STRATEGIC_OPTIONS_TEXT}}` → актуальное содержимое `output/options.md` (после пересчёта на усиленные находки).
3. Отправить промпт в Zcode; получить разбор по 4 векторам (юнит-экономика, трение адаптации, контр-ходы конкурентов, **эпистемический аудит фактов** — вектор №4 дополнительно проверяет находки TICKET-12 на остаточные слабые утверждения).
4. Итог сохранить в `knowledge/projects/demo-megafon/output/adversarial-review.md`; прежнюю версию сохранить архивным блоком `### Архив (волна 1, замещено 2026-11-22)` в конце файла.
5. Если GLM не предлагает контрмеры из контракта TICKET-09 (99 ₽, ARPA 1 650 ₽) — это нормально: тогда **обновить контракт раздела 3.1 спеки TICKET-09** под фактическое содержание реального разбора (реальность важнее соответствия старой спеке), либо попросить GLM явно оценить эти две контрмеры.
6. Дописать в `state/cost-log.csv` строку `entry_type: measured` с реальными токенами GLM 5.3.
7. Сцена для видео: окно Zcode с отправленным промптом и генерацией разбора (блок 04:45–06:45 VIDEO-PLAN).
